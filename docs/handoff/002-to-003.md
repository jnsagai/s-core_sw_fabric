# Handoff: increment 002 to increment 003

Increment 002 now produces bounded, sealed draft work-product plans. Increment 003 may consume
only a plan whose schema version, self-digest, selected catalogue/profile/mapping digests, and
closure status it validates independently. A blocked draft is review evidence and must not be
compiled into an executable workflow.

## Available inputs for 003

- `schemas/work-product-plan.schema.json` and the runtime plan contract.
- Stable instance identity:
  `(target_namespace, native_source_id, native_work_product_id, scope_kind, scope_id, purpose)`.
- Explicit origin rule IDs, requesting scopes, template/review references, dependency IDs,
  applicability, requested/effective dispositions, and stable findings.
- Deterministic canonical bytes under relocation and set-like input permutation.
- A selected 74-work-product baseline and review-draft mapping for integration tests.

## Compiler prerequisites

1. Revalidate the plan digest and reject unsupported schema versions.
2. Require `planning_status: complete` and `closure_complete: true`; never infer readiness from
   plan file existence.
3. Preserve logical instance IDs and origin/source references in every generated node and source
   map.
4. Treat dependency IDs as obligation dependencies, not accepted execution ordering. Define
   scheduling/gate semantics explicitly in 003.
5. Reject dangling instances, dependencies, required reviews, and disposition states that 003
   cannot compile safely.
6. Keep native work products outside Fabro run state. Generated graphs may reference artifacts but
   cannot replace their authority or edit them implicitly.
7. Preserve `plan_kind: draft` and `engineering_readiness: not_evaluated`; workflow compilation
   does not promote either field.
8. Add drift tests binding generated workflow content to the exact plan/catalogue/policy digests
   and compiler version.
9. Continue to exclude runtime/model calls and protected approval verification unless their owning
   increments are explicitly activated.

## Known unresolved inputs

account for the selected catalogue but do not constitute owner-approved engineering applicability.
The security process/template FDR ID conflict remains a blocking finding. Effective reuse and
tailoring remain unavailable until increment 005 provides protected authority verification.
Full score/module_template documentation builds and the existing human review checklists remain
open.
