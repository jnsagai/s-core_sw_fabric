3. **External identity and source provenance.** `docs-as-code/src/helper_lib/external_needs.py` supports `@repo//pkg:needs_json`, `@repo//pkg:needs_json_file`, and same-repo `//pkg:...`; runfiles roots are `{bazel_module}+/...` versus `_main/...`. `src/extensions/score_metamodel/external_needs.py:add_external_needs_json` registers `base_url = project_url + '/main'`, without an ID prefix; bundle exports intentionally clear `project_url`. Thus URL/main is a rendered location, not immutable source identity, and an empty URL is not necessarily invalid. Native IDs can collide across separately imported repositories; qualify internal identity without rewriting native IDs. `docname` and `lineno` occur in native records; bundle-mounted `docname` is not guaranteed to equal checkout-relative source path. Preserve native path and a separately justified source-path mapping, plus unavailable location state.

Module template RST contains draft `document` instances tagged `template` and nested `code-block:: rst` examples; example directives are not independently instantiated Needs. Broad RST regex scanning will produce false instances and miss resolved needs/needextend effects. Prefer native export for instance data and retain metamodel source as the rule contract.

5. **Relations have distinct semantic direction.** `metamodel.yaml:1024` defines `contains`, `has`, `input`, `output`, `responsible`, `approved_by`, `supported_by`, `complies`, `realizes`, `affects`, `derived_from`, `covers`, `consists_of`, `belongs_to`, `satisfied_by`, `satisfies`, `fulfils`, `implements`, etc. `satisfies` and `fulfils` are explicitly compatibility forms; do not collapse distinct outgoing/incoming directions, inferred backlinks, or narrative `:need:` references into uniform evidence edges. Schema fields identify `field_type: links` versus `backlinks`; use that distinction and keep unsupported fields losslessly.
